## Core Capabilities
- Messaging Bot: The bot runtime is the front door for users. It connects to the messaging platform with a token, watches incoming messages, decides which messages should receive a reply, and gives users a response in the same channel or conversation. Key concepts: bot runtime, message events, mentions or commands, platform token.
- AI Responses: The response step prepares the user question, recent context when available, and retrieved documentation snippets for the configured model provider. It should stay grounded in the provided docs and fall back to a simpler response when the provider is unavailable. Key concepts: model provider, grounded prompt, retrieved context, fallback response.
- Conversation Memory: Conversation memory is the short-term context layer for chat-style products. It groups recent messages by user, channel, session, or conversation, keeps the history bounded, and expires stale context so answers can be relevant without storing unlimited chat data. Key concepts: recent messages, conversation context, session timeout, bounded history.
- Documentation Lookup: This workflow turns a user question into usable documentation context. It sends the question to the configured documentation source, parses the returned sections, keeps useful metadata such as titles and source links, and hands the best context to the response step. Key concepts: docs retrieval, query text, source links, code examples.

## Configuration You May Need
- `BOT_TOKEN` - Bot token used to log the messaging client into the platform.
- `DISCORD_CLIENT_ID` - Discord application client ID used when configuring or inviting the bot.
- `OPENAI_API_KEY` - OpenAI API key used when the project generates AI answers from retrieved context.
